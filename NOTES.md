# ImageRing app: build notes


## Layout

- `Sources/RingGeometry.swift`, `RingModel.swift`, `RingView.swift`: unchanged (verbatim). No new hooks were needed: `RingView.selection(at:)`, `RingState.openProgress/submenuProgress` and `RingView.pngData` cover everything.
- `Sources/main.swift`: entry point and debug modes (`--render`, `--run`, `--selftest`, `--demo`, `--log <path>`).
- `Sources/App.swift`: status bar item (`circle.circle`, menu "Hotkey: ⌃⌥Space" disabled, "Quit ImageRing") and hotkey wiring.
- `Sources/Hotkey.swift`: Carbon hotkeys (⌃⌥Space pressed/released; Esc registered only while open). Same plumbing as `spike/main.swift`.
- `Sources/FinderSelection.swift`: Finder selection via NSAppleScript (blocking), filtered by `UTType.conforms(to: .image)`.
- `Sources/RingPanel.swift`: non-activating NSPanel (512x512 = `RingGeometry.canvasSize`), 60 Hz timer for hover, open/submenu animation, hold/tap logic, click handling, and the pure functions `releaseMode`, `resolve`.
- `Sources/Actions.swift`: all actions, output naming, copy, notifications.
- `build.sh` builds `build/ImageRing.app` (ad-hoc signed, not installed). `Info.plist` has the required keys.
- `test/run_tests.sh`: 41 cases. Fixtures are generated by `test/tools/make_fixtures.swift`. `test/tools/probe.swift` reads metadata and corner colours through ImageIO.

## Decisions

- Hold release on a slice that has a submenu (no sub-item under the pointer) cancels. Tap-click on that slice keeps the ring open.
- Hold release that happens while the Finder read is still blocking is stored and acted on after the read.
- Convert writes `<name>.<ext>` with no suffix (the brief's rule). Collisions give `-2`, `-3`.
- Compress calls the existing `~/.local/bin/img-shrink` unchanged. Its outputs are `<name>-500KB.jpg` (always JPEG), which differs from the general `<name>-<suffix>.<ext>` rule. The app does not send a second notification.
- Strip re-encodes with ImageIO thumbnails and no property dictionary. ImageIO still writes a minimal `{Exif}` block (ColorSpace, PixelX/YDimension) and `{JFIF}`. No camera, date, GPS or Make tags survive.
- Copy writes one NSPasteboardItem with PNG data and `public.file-url`.
- WebP is hidden by `RingModel.slices(webpAvailable:)` when `/opt/homebrew/bin/cwebp` is missing, so no notification text is needed.
- Reduce Motion sets `openProgress` and `submenuProgress` straight to 1.

## Gotchas found while testing

1. `NSPasteboardItem.setString(_, forType: .fileURL)` did not register `public.file-url`. `setData(Data(absoluteString.utf8), forType: .fileURL)` does.
2. `clearContents()` must come before creating the item. Creating the item first lost the file URL.
3. A CLI process that exits right after `writeObjects` can lose the file URL. Reading `pb.types` in-process does not prove the server has it. The fix is `RunLoop.current.run(until: +0.5 s)` before returning. Verified 4 of 4 with `clipcheck` after each copy.
4. `sips -r 270` rotates counter-clockwise (marker top-left goes to bottom-left), which matches the brief's "↺90 = -r 270". Checked by pixel.
5. `design/shots/open-half.png` cannot be reproduced by rendering that state alone. Rendering `open-half` in isolation with the design's own code gives output identical to the app's (0 differing pixels). The shot differs by 1947 pixels (max diff 69/255), so it was apparently rendered after other states in one process. The other 9 states match the shots byte for byte.
6. Tests call img-shrink, which sends its own notifications (2 per run). `--run` itself sends none. Copy overwrites the clipboard.

## Unverified / not done

- Live hotkey press. Two osascript key injections (`key code 49 using {control down, option down}`) reached neither the app nor a minimal probe, and the status-bar process still held the hotkey. A later extra keystroke was blocked by the auto-mode classifier, so key injection was stopped. Not verified: hold mode with real timing, tap-then-click, Esc, click-outside.
- Mouse tracking, hover, submenu open and click inside the live panel. Only `--render` and `--demo` (launch and stay alive, no input) were run.
- Finder frontmost gating and the Finder Automation (TCC) prompt on a fresh machine.
- Compress "Custom…" (opens img-shrink's dialog; not run in tests).
- Hover cross-fades (90 ms slice, 70 ms sub-item) and the 60 ms arc fade-out. `RingState` has no fields for them, so they are not implemented. The arc disappears at once when the pointer leaves it.
- Status-item click and menu. Only the launch (START line) was checked.
- Panel on a multi-display setup or on a full-screen Finder space.
